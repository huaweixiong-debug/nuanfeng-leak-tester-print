# 操作员硬件配置指引（扫码枪 / 打印机 / 串口）

本页说明 Web UI 中新增的设备配置项。所有配置保存在服务器上的
`line_settings.json`（与历史设置同一文件），重启服务后仍然生效。

## 1. 登录与首次初始化（浏览器本地账号）

- 账号仍保存在浏览器 localStorage（与旧版一致），不写入服务器。
- 全新浏览器或从未配置过 admin 的机器：设置页顶部会出现“初始化 admin”面板。
  - 用户名固定为 `admin`；输入自定义密码并再次确认后点击“初始化 admin”。
  - 不会自动登录；初始化后请用该密码正常登录。
  - 已存在 admin 时该面板自动隐藏，admin 账号与密码不会被覆盖或重置。
- 每个浏览器各自初始化自己的账号；换电脑/换浏览器需重新初始化。
- 刷新页面后需要重新登录（与旧版一致）。

## 2. 扫码枪开关与串口

- 位置：设置页 → 产品设置卡片顶部“设备通信”。
- 「扫码枪」开关关闭时：
  - 不会打开串口、不会自动重连；
  - 「需要扫码」「扫码启动」会自动关闭；
  - 已暂存的扫码绑定会被清除。
- 「扫码枪串口」留空表示使用默认值（环境变量 `SCAN_SERIAL_PORT`，默认 COM7）；
  也可直接输入 COM1/COM3 等实际端口（下拉会列出本机已识别端口）。

## 3. 仪器串口

- 「仪器串口」留空表示使用默认值（环境变量 `ATEQ_SERIAL_PORT`，默认 COM8）。
- 修改串口会先关闭当前串口句柄，下一次通讯使用新端口；服务重启后会自动
  加载已保存的仪器串口，无需再次保存。
- 仪器与扫码枪不能配置为**实际**同一串口（包含留空时的默认端口回退）：
  例如扫码枪留空（默认 COM7）时仪器不能再填 COM7；扫码枪禁用时不受此限制。
- 本机当前可用端口以“串口下拉列表”为准，不要凭猜测分配：COM1 与 COM3
  的具体设备对应关系必须由现场确认。

## 4. 打印机（Zebra ZT231 / USB001）

- 「打印机」开关关闭时不会调用 BarTender，也不会解析打印机队列。
- 开启打印时，系统按 Windows 端口 `USB001` 解析打印队列（当前为
  Zebra ZT231），并使用 BarTender 命令行 `/PRN=<队列名>` 选择打印机
  （`/P` 表示执行打印，`/X` 表示退出）。
- 解析失败（找不到 USB001 或无该端口的队列、匹配到多台）会阻止打印并给出
  明确报错，绝不会回落到默认打印机。

## 5. 运行中修改设备配置

- 测试运行期间不允许修改串口或扫码枪开关，接口会返回
  `TEST_ACTIVE`，且不会写入任何配置（保存与测试启动互斥）。
- 空闲时修改：扫码枪会先确认旧线程已停止，再按新端口重启；仪器串口立即生效
  （断开旧句柄）。任何一步失败都会返回 `restart_required`，需要重启 Web UI 服务。
- 如果扫码枪线程在规定时间内未能停止，系统会保持真实运行状态、阻止启动新线程
  并阻止旧事件被用于启动测试，直到重启服务。

## 6. 验证与回归（离线，不下发硬件命令）

```bat
set ATEQ_DISABLE_HARDWARE=1
python -m unittest discover -s tests -q
python -m py_compile webui_server.py line_runtime.py serial_scanner.py program_selector.py modbus_utils.py bartender_print.py
python tests/extract_js.py %TEMP%\embedded_ui.js && node --check %TEMP%\embedded_ui.js
```

上述命令不连接仪器、不打印、不访问生产数据。真机端到端（COM 对应关系、
实际标签打印）必须由现场操作员在确认端口后单独验证。
